# はじめに
プラゴのバックエンドエンジニアの山浦です。エキスパート（んーテックリードに近いですかね）とマネージャーを兼任しております。今回はプラゴのエンジニアが実際にどういうツールを使って開発しているのかをご紹介します。

## Slack
チャットのやり取りはこれになります。最近はHuddleもあるので、パッと話したい時にもこれを使ってます。

## Jira/Confluence
Atlassian系のツールを採用しています、スクラム開発をしているのでJiraはスクラムのテンプレートを使っています。
ConfluenceはDesign Docなど開発時に使うツールや運用などの情報をまとめています。


## ChatGPT
使い方は特に指定していないですが、ドキュメントを書いたり技術のキャッチアップや壁打ちで使ってます。
スクラムガイドを読み込ませてスクラムの運用について聞いたり、EV充電業界のプロトコルの仕様書などを読み込ませて効率的に情報を収集、把握できる状態にしています。

## GitHub
ソースコードはGitHubを採用しています。元々はGitLabを使っていましたが

- Slackと連携しやすい
- GitHubでの実装方法のテンプレや記事が多く、新しいツールの導入が楽
- 使い方にもよりますが、今のプラゴの使い方だとGitLabより安い

という観点から移行しました。チームのみんなからもいい反響があり、やってよかったと思います。

## Node.js
プラゴのサーバは主にNode.jsを使っています。Nestjsというフレームワークを採用しており、モジュラーモノリス構成になっています。

## TypeScript
Node.jsで実装する際にはTypeScriptで書いています。

## Docker/DockerCompose
サーバは基本コンテナで動かしており、LocalではDocker Composeで制御しています。

## Postman
REST/gRPCのAPIを再現する際に使ってます。エンジニアが開発中のAPIを試すだけでなく、QAチームがテストを書いて一部のAPIのテスト自動化でも利用しています。PostmanはSwaggerとの相性もいいので、OpenAPIを使っているチームにはおすすめです


## クラウド：GCP
主にGCPを利用しています。
利用しているサービスは
- Cloud DNS
- Cloud SQL
- MemoryStore
- Google PubSub
- GKE
などなどです。

今後もGCPから乗り換える予定はないですが、他のクラウドにしかない機能はそれを使うなど柔軟な考えで選定するつもりです。

## Terraform
GCPのリソース管理に使っています。学習コストはありますが、IaaSがあることで安全に安心に運用できるというメリットの方を大きく享受できている実感があります。

## Datadog
ログを集約、確認するために使っています。

## K6
最近負荷試験を実施することがあり、K6を導入しました。TypeScritで書けること、K8sなどに組み込みやすいことも考えこちらを選定しました。あまり知見がないので活用はこれからになりそうです。


# おわりに
いかがだったでしょうか？EV充電業界って聞くと古い、お堅いイメージかもしれないですが、プラゴの場合どっちかっていうとWeb系の会社と使っているツールや雰囲気は近いです。基本は効率が上がるなら積極的に導入しますし、チームのメンバーからの発案や意見を採用することも多い方かと思います。
